## 우선 수정할 부분

### 1. 높은 우선순위: 하위 객체 복제 실패 시 원본 수정 경로 차단

README의 “공유 참조라면 하위 객체도 별도로 복제한 뒤 정리” 방향은 맞다. 이미 CloneSubObject가 있지만 실패 처리가 부족하다.

- `CustomTagRegistrySupport.cs:308–320`: 곡의 하위 객체 복제가 null을 반환해도 TryCloneMusicInfo는 true를 반환한다. 이후 `276–277`에서 얕은 복사로 공유한 m_MusicExInfo를 정리할 수 있다.
- 같은 파일 `141–150`: 앨범도 복제가 실패하면 원래 albumExInfo에 CleanPurchaseProperties를 호출한다.
- ModReflection.SetValue는 bool로 실패를 알리지만 복제본 연결 결과를 검사하지 않는다. 곡은 연결 실패 후 다시 읽은 공유 객체를 정리할 수 있다.

개선: 복제 성공과 부모에 연결 성공을 확인하고, 실패 시 해당 가상 콘텐츠 주입을 중단한다. IL2CPP 객체는 관리형 래퍼의 참조 비교만으로 판단하지 말고 네이티브 Pointer가 원본과 분리됐는지 확인한다. 정상/복제 실패/연결 실패에서 원본 상품 메타데이터가 유지되는지 검증한다. 이는 코드상 가능한 실패 경로이며 실제 원본 변경을 재현한 결과는 아니다.

### 2. 중간 우선순위: AP 설정 설명과 정확도 훅의 동작 통일

README:279는 EnableAPMod가 배너와 정확도 오버라이드를 제어한다고 설명한다. 그러나 APModPatch.cs의 GetAccuracy, GetTrueAccuracy, GetTrueAccuracyNew Postfix는 EnableAPMod를 검사하지 않고 ShouldApplyExperimentChart만 검사한다. AddScore와 IsFullCombo에는 설정 검사가 있다.

따라서 설정을 꺼도 커스텀 차트의 정확도 오버라이드는 남는다. 체크리스트의 “기능을 끄는 게이트를 쓰는 쪽에만 달지 말 것”을 적용할 실제 대상이다. 다만 커스텀 정확도가 올바른 기록 계산에 필수라면 무조건 끄지 말고, 배너 옵션과 정확도 보정 옵션의 의미를 분리한 뒤 문서도 맞춰야 한다. 검증은 순정/커스텀 곡 각각에서 옵션 on/off로 수행한다.

### 3. 중간 우선순위: dotnet build 배포 실패를 성공으로 표시

체크리스트의 지적은 현재도 정확하다. csproj:50의 Copy는 WarnAndContinue이고 :52의 성공 메시지는 무조건 실행된다. 직접 dotnet build 시 DLL 복사가 실패해도 성공 메시지가 나올 수 있다.

개선: 복사 실패를 타깃 실패로 전달하고 성공한 경우에만 성공 메시지를 출력한다. 산출물과 Mods 대상 DLL의 해시도 대조한다. build.bat은 별도의 copy 종료 코드와 파일 크기를 검사하므로 동일한 무검증 경로로 취급하면 안 된다. DLL 잠김에 의한 복사 실패도 검증한다.

### 4. 문서 갱신: 이미 바뀐 동작을 옛 방식으로 설명

- README:21의 “에셋 키 참조를 차단”은 체크리스트의 MusicInfo.music 에셋 키 보존 지침 및 TryCloneMusicInfo/InjectVirtualSong의 현재 설명과 충돌한다. 표시 제목은 로컬라이즈 경로에서 바꾸고 원본 음원 에셋 키는 보존한다고 고쳐야 한다.
- README:111의 `record/{uid}_{난이도}.json`은 일반 곡의 현재 저장 규칙이 아니다. CustomRecordStore.ResolveRecordKey는 곡 폴더 이름을 쓰며, 폴더를 해석할 수 없거나 hwa 루트인 경우에만 UID로 폴백한다. BMS 지문 검사도 이미 존재하므로 새 개선 과제로 중복 구현하지 않는다.
- MOD_SYSTEM_BLUEPRINT의 정확도 공식은 분모가 양수인 현재 구현과 일치한다. 다만 분모가 0이면 perfect/great/miss 합으로 계산하고, 그 합도 0이면 1.0을 반환하는 경계 동작이 빠졌다.

## 판단

원본 데이터 보존, 기능 게이트 일관성, 실제 배포 확인이라는 개선 방향은 타당하다. 우선순위는 하위 객체 복제 실패 처리 → AP 옵션 의미 정리 → 배포 실패 전파 → 오래된 문구 갱신이다. 구현 전 확인해야 할 사항과 이미 구현된 사항을 구분해야 한다.

코드 수정 후에는 CHECKLIST.md에 따라 빌드 및 Mods 산출물 확인, 정상 곡 배틀, BMS/앨범 없음 → 0-0 폴백 → 실제 배틀 진입까지 별도로 검증해야 한다. 이번 정적 점검으로 그 실행 검증을 대신할 수 없다.
