## 3. 업데이트 내성 감사와 고친 것

### 3.1 이미 있는 장치 (확인만)

- `PatchInstaller`: 패치 메서드를 미리 JIT 해 보고, 컴파일 안 되거나 대상이 사라진 패치는 걸지 않음. 다중 대상 클래스는 남은 대상만 부분 적용.
- `PatchHealthCheck`: 대상 해석 결과를 시작 시 요약. 타입이 사라져도 클래스마다 격리.
- `FeatureGuard`: 매 프레임 기능 10회 연속 실패 시 자동 비활성, 씬 전환 때 재무장.

이 셋은 **"메서드가 사라진 업데이트"** 를 잡습니다. **"메서드는 그대로인데 동작이 바뀐 업데이트"** (6.7.0의 `BGM_OneShot` 사고)는 아무 경고도 남지 않았습니다.

### 3.2 게임 버전 경고 추가 — `GameVersionCheck`

- 위치: [GameVersionCheck.cs](../../muse%20dash%20test/Core/GameVersionCheck.cs), 호출은 [MainMod.cs](../../muse%20dash%20test/MainMod.cs) `PatchHealthCheck.Run()` 바로 뒤.
- `Application.version`을 검증 버전 `6.7.0`과 숫자로 비교합니다(`6.10.0` > `6.7.0`, `6.7` = `6.7.0`). 같으면 `[GameVersion] 게임 6.7.0 (검증 버전과 같음)` 한 줄, 다르면 경고 한 줄입니다. **기능은 끄지 않습니다.**
- 새 게임 버전에서 실기 검증을 마치면 `VerifiedGameVersion`을 함께 올리십시오. 테스트 9개(`GameVersionCheckTests`).

기대 효과는 작습니다(스캔은 밀리초 미만이 보통). 실측된 렉 원인은 이미 고친 `getContent` 풀 디코딩이었습니다.

### 9.3 CI가 만든 날부터 빨간불이던 것

GitHub Actions `Logic Tests`(2026-11-18 도입)는 **한 번도 통과한 적이 없었습니다**(`gh run list`: 매 푸시 실패 23개). 로컬(Windows)에서는 전부 통과해 아무도 몰랐습니다.

- **원인 1 — 실제 코드 결함**: `BmsWavParser.ParseWavName`이 `#WAV` 값(`1번 씬 wav폴더\011001_….wav`)에서 폴더를 `Path.GetFileNameWithoutExtension`으로 잘랐는데, 이 API는 실행 OS의 구분자만 봅니다. ubuntu에서는 `\`가 구분자가 아니어서 UID를 못 읽었고, 그 여파로 홀드 짝 맞추기·보스 전환·실제 채보 테스트 20개가 연달아 실패했습니다. Linux 계열 런타임(Android 포함)에서 Windows에서 만든 채보를 읽으면 같은 일이 납니다. 두 구분자를 직접 자르도록 고치고 테스트 1개(`ParseWavName_StripsFolderPrefixWithEitherSeparator`)를 더했습니다. Windows 동작은 그대로입니다.
- **원인 2 — 테스트 픽스처**: 나머지 3개(`BmsChartSet.Describe`·`TryResolveInSongFolder`, `BmsFileNames.IsTempFile`)는 `H:\songs\…` 같은 Windows 절대 경로를 픽스처로 씁니다. 모드가 도는 OS가 Windows이므로 CI 러너를 `windows-latest`로 바꿨습니다.
- 재발 방지: [CHECKLIST](../guides/CHECKLIST.md) 1절(채보에서 읽은 경로를 `Path`로만 자르지 말 것)과 4절(릴리즈 전 `gh run list`로 CI 확인)에 항목을 넣었습니다.

- **`KeysoundProbe`의 키음당 비용**: Prefix/Postfix가 키음마다 IL2CPP 호출 6회 남짓(`isPlaying` 2회, `m_DbOther`, `frameCount` 등)을 합니다. 타격당 수 µs 수준이고, 사용자가 계측을 상시 유지하기로 정했으므로 그대로 둡니다. 끄는 스위치가 필요해지면 `ModConfig`에 항목을 두고 두 패치 본문 첫 줄에서 보십시오.
- **`SaveSelectionGuard`는 `DataManager.Save`가 던지면 되돌리기를 못 합니다**(Postfix 생략). 클래스 주석대로 곡 선택 화면이 바닐라 기본 태그로 돌아갈 뿐이라 그대로 둡니다. Finalizer로 바꾸면 항상 되돌릴 수 있지만, 이 저장소는 IL2CPP 대상에 Finalizer를 쓴 적이 없어 실기 확인 없이 넣지 않았습니다.
- **로컬 브랜치 `feature/hold-dt-frames`**(와 그 사본 `local/feature/hold-dt-frames`)는 AGENTS.md 5항의 '일반 노트 uid별 도착 시각 차이' 실험을 보관하는 브랜치라 지우지 않았습니다. 1.2절의 `feature/skill-counter-999`·`feature/yume-gear-smash`는 이 클론의 로컬 브랜치에는 없고 로컬 미러 원격(`local`, `H:\local-repos\muse dash test.git`)에만 남아 있습니다. 병합·삭제는 여전히 사용자가 정할 일이라 그대로 두었습니다.

### 9.5 릴리즈 전 추가 (v0.16.1)

- **병목**: `KeysoundProbe.PollMarkKey`가 메뉴·로딩에서도 매 프레임 `Input.GetKeyDown(F8)`(IL2CPP 호출)을 했습니다. 배틀 밖 F8은 지난 배틀 기록을 다시 찍을 뿐이라 `HywStageManager.IsInStageStatic`(관리 플래그)을 먼저 봅니다. `config.txt` 감시(`LoadConfigIfNeeded`)가 배틀 중을 거르는 것과 반대 방향의 같은 원칙입니다.
- **릴리즈 자동화**: v0.16.0까지 릴리즈 노트·태그·DLL 첨부를 손으로 했고, CI를 보지 않아 빨간불인 채 릴리즈 4개가 나갔습니다(9.3절). `tools/release.ps1`이 버전(`ModInfo.Version`)·`CHANGELOG.md` 항목·main 동기화·HEAD의 CI 통과를 확인하고, Release 빌드(`-p:SkipDeploy=true`로 Mods 복사 생략)·로직 테스트를 돌린 뒤에만 태그를 푸시하고 `gh release create`로 DLL을 올립니다. 릴리즈 노트 원본은 이제 `CHANGELOG.md`입니다.

## 10. 감사 7차 (2026-11-23 — v0.16.2)

정적 감사(게임 미실행, 클라우드 환경이라 모드 본체 빌드 불가 — CI 로직 테스트로만 확인).

**고친 것**
- `InputOverlay.LoadConfigIfNeeded`: 수정 시각을 파싱 **전에** 기록해서, 메모장이 파일을 비우고 다시 쓰는 순간이나 잠가 둔 순간에 읽으면(빈 텍스트 또는 `IOException`) 그 변경이 다음 저장까지 반영되지 않았습니다. `ParseConfigFile`이 성공 여부를 돌려주고, 성공했을 때만 시각을 기록합니다. 같은 시각에서는 최대 5번(1초 간격) 다시 읽고 그래도 실패하면 경고 한 줄을 남깁니다.
- `Patch_SkinNameProbe`(`SpineActionController.Awake` Postfix, 노트·캐릭터가 생길 때마다 호출): 본문 첫 줄에서 돌아가도 IL2CPP 트램펄린 비용이 노트마다 들었습니다. `Prepare()`로 `EnableSpineSkin && Verbose`일 때만 겁니다. 이를 위해 `MainMod.OnInitializeMelon`에서 `DeviceDetector.Detect`·`ModConfig.Load`를 `PatchInstaller.ApplyAll` 앞으로 옮겼습니다(둘 다 패치에 의존하지 않음).
- `AllPerfectSound.IsFullComboClip`(모든 효과음의 `PlayOneShot` 훅): `clip == null`(Unity `op_Equality`)을 `clip is null`로.

**점검했지만 바꾸지 않은 것**
- `KeysoundProbe`는 키음마다 `AttacksController.PlayOneShot`(Prefix+Postfix, 문자열 인자)·`ShowAttackEffect`에 붙어 있어 노트마다 비용이 듭니다. 사용자가 계측 유지를 결정했으므로 그대로 둡니다. 꺼야 하면 같은 `Prepare()` 방식으로 `MelonPreferences` 토글에 묶으면 됩니다.
- `OffsetHookPatches`의 `DBStageInfo.delay` getter Postfix는 세션 UID가 있으면 사전 조회 한 번이라 값쌉니다.
- 600줄 넘는 소스 파일 없음(최대 433줄).
