# 홀드 막대 길이와 dt (해결)

속도 2·3 홀드의 꼬리가 판정 시각보다 일찍 판정선을 지나가던 문제와, 그 해결로 확정한 홀드 dt를 정리한 문서입니다.
**홀드와 보스 발사체는 채보 WAV `_dt`를 맞춰 확정했습니다(2026-10-24 실기 검증). 남은 것은 일반 노트 계열입니다(5절).**

- 조사·검증일: 2026-10-24, 게임 6.7.0, 모드 v0.11.0
- 모드 코드는 바꾸지 않았습니다. 모드는 dt를 WAV `_dt` 그대로 씁니다([NOTE_SPEED_DT.md](NOTE_SPEED_DT.md)).
- 처음 발견한 곳: Star Trace(`hwa\Star Trace\hwa2.bms`, BPM 175) 100마디 = 137.1429초.
  공중 홀드 꼬리(속도 3)와 지상 홀드 머리(속도 3)가 같은 박자인데, 지상 머리가 꼬리보다 늦게 오는 것처럼 보였습니다.

---

## 1. 노트 계열별 dt (사용자 확정, 2026-10-24)

채보 WAV 이름의 `_dt`에 적는 값입니다.

| 노트 종류 | 속도 1 (느림) | 속도 2 (보통) | 속도 3 (빠름) | 상태 |
| --- | --- | --- | --- | --- |
| 일반 / 트랩 / 음표 | 1.48 | 1.28 | 1.08 | 속도마다 0.20초 간격. **렌더-판정 일치는 아직 확인 안 함(5절)** |
| 홀드 | 1.47 | **1.26** | **1.10** | 실기 검증 완료. 꼬리 렌더 오차 0ms |
| 보스 발사체 | 0.8 | **0.76** | **0.6** | 실기 검증 완료(탄막 속도). 속도 2·3은 확정값 |
| 고정 이벤트: 씬 전환(`0004yy`) / 보스 액션(`0101xx`) | 0 | 0 | 0 | 속도와 무관 |

## 2. 원인: 비유

홀드는 **기차**입니다. 머리가 기관차, 막대가 객차, 꼬리가 마지막 칸입니다.

- 기관차(머리)는 출발 시각(`showTick = tick − dt`)에 떠나서 **dt초 만에** 역(판정선)에 닿도록 달립니다.
  dt를 작게 적으면 그만큼 빨리 달려 정시에 도착합니다. 그래서 머리는 dt를 몇으로 적어도 정시에 옵니다.
- 그런데 객차 길이(막대 길이)는 게임이 **속도 단계별 고정 시간표**로 정해 둡니다. 속도 3 기차는 1.10초 걸려 오는 속도로 달린다고 보고 객차를 붙입니다.
- 속도 3 홀드를 `_dt1.07`로 적으면 기차가 시간표보다 2.7% 빨리 달리는데 객차는 시간표대로 짧습니다.
  그래서 **마지막 칸(꼬리)이 예정보다 일찍 역을 지나갑니다.** 기차가 길수록(홀드가 길수록) 더 일찍 지나갑니다.
- 해결은 기차를 시간표대로 달리게 하는 것, 즉 **홀드 `_dt`를 막대의 고정 시간에 맞추는 것**입니다.

Star Trace 100마디에서는 옆 선로(지상)의 기관차가 정시에 들어와, 일찍 지나간 공중 마지막 칸과 나란히 보이면서
"지상 기관차가 늦게 왔다"처럼 보였습니다.

## 3. 측정 (2026-10-24, Star Trace, 홀드 `_dt1.07` 상태)

노트가 판정 시각을 지날 때 머리 오브젝트 위치와, 머리에 붙은 막대 스프라이트(`0402_air_renderer`, 끝 캡 `s00_press_end`)의
x 범위를 찍었습니다. 판정선 x는 −3.86이고, 막대는 머리와 한 덩어리로 움직입니다.
꼬리 노트 오브젝트 자체는 (0,0)에 고정이라 그려지는 위치와 관계가 없습니다.

| 홀드 | 길이(초) | 실제 이동 속도 | 막대가 가정한 속도 | 꼬리 도착 − 판정 시각 |
| --- | --- | --- | --- | --- |
| #6·#8 속도 1 (공중·지상, `_dt1.47`) | 2.74 | 9.435 u/s | 9.457 u/s | +0.006초 |
| #10 속도 3 공중 (`_dt1.07`) | 1.37 | 12.963 u/s | 12.606 u/s | **−0.038초** |
| #11 속도 3 지상 (`_dt1.07`) | 1.03 | 12.963 u/s | 12.606 u/s | −0.028초 |
| #12 속도 3 공중 (`_dt1.07`) | 0.51 | 12.963 u/s | 12.606 u/s | −0.014초 |

- 실제 이동 속도 = 머리가 이동한 거리 ÷ 걸린 시간(머리 tick → 꼬리 tick)
- 막대가 가정한 속도 = 머리 tick 순간의 막대 길이 ÷ 홀드 길이
- 출발점~판정선 거리(약 13.87)로 바꾸면, 이동은 13.87 ÷ 12.963 = **1.070초(= `_dt`)**, 막대는 13.87 ÷ 12.606 = **1.100초**입니다.
- 지상 머리를 32분 한 칸(0.0429초) 앞당기면 맞아 보였던 이유: #10 꼬리가 0.038초 일찍 지나가는데, 32분 격자가 그 값에 가장 가까웠습니다.

## 4. 해결 (2026-10-24 실기 검증)

| 속도 | 홀드 `_dt` | 막대 기준(프레임/30) | 검증 |
| --- | --- | --- | --- |
| 1 | 1.47 | 44프레임 = 1.4667초 | 측정 오차 +0.006초 |
| 2 | **1.26** | 38프레임 = 1.2667초 | 1.33 → 1.30 → 1.24 → 1.28 → 1.26 A/B 실기 시험. 1.26에서 꼬리와 다음 정박 머리가 일치 |
| 3 | **1.10** | 33프레임 = 1.100초 | 꼬리가 판정 시각에 오차 0ms로 도달 |

속도 3 홀드는 같은 속도 3 일반 노트(1.08)보다 약 2% 느리게 흘러갑니다. 막대 기준에 맞춘 결과입니다.

## 5. 남은 일: 일반 노트 계열

**일반 노트 / 트랩 / 음표도 홀드·보스 발사체처럼 렌더와 판정이 정확히 맞는지 찾아야 합니다.** 1절 값(1.48 / 1.28 / 1.08)은
"속도마다 0.20초 간격"으로 정한 것이고, 홀드처럼 실제 도착 위치를 재서 확인한 값은 아닙니다.

볼 곳:
- 일반 노트는 홀드와 달리 몸체(오브젝트 위치)가 움직이지 않고 Spine 뼈대 애니메이션으로 날아옵니다(이번 측정에서 몸체 x 속도 0).
  그래서 홀드처럼 오브젝트 위치로는 잴 수 없고, Spine 뼈대 위치나 화면 렌더러 범위로 재야 합니다.
- 공식 곡의 등장 애니메이션 길이: 속도 1 `in_nor_44` = 1.4667초, 속도 2 `in_nor_38` = 1.2667초, 속도 3은 아직 모름
  ([NOTE_SPEED_DT.md](NOTE_SPEED_DT.md) 2절). 지금 dt(1.48 / 1.28)와 0.013초씩 다릅니다.
- 비교 기준으로는 같은 박자에 정박이 확인된 노트(검증된 홀드 머리·꼬리)를 옆에 두는 방법이 이번에 잘 통했습니다.

## 6. 원인이 아니었던 것

| 후보 | 결과 |
| --- | --- |
| 두 노트의 dt 차이 | 공중 꼬리·지상 머리 모두 dt 1.07, showTick 136.07로 같음 |
| 꼬리 늦은 생성 | `SpineActionController.OnControllerStart` 기준 꼬리·머리 모두 136.066에 같은 프레임 생성 |
| 예전 "동시치기 짝 큰 dt 통일" 로직을 뺀 탓(`0913189`) | 그 로직은 일반 노트 짝에만 적용돼 홀드에 쓰인 적이 없음 |
| v0.11.0 스폰 지연 보정(`NoteAnimationSyncPatch`) | 홀드는 `PlayByKey("in")`을 타지 않아 이 보정이 걸리지 않음 |
| 몸통 간격·꼬리 tick 규칙 | 공식 곡(48-4)과 같음: 몸통 0.1초 간격, 꼬리 tick = 머리 + 길이, `showTick = tick − dt` |
| 같은 tick·다른 레인 처리 | 지상 노트가 없는 169.54초(#12)에서도 꼬리가 같은 비율로 일찍 지나감 |
| 한 레인 전체가 밀림 | 모든 홀드 머리가 레인·속도와 상관없이 판정 시각에 같은 x(−3.86)에 닿음 |

홀드를 잇는 필드(`longPressPTick`·`endIndex`·`longPressNum`)는 공식과 모드가 다르게 채웁니다(공식 머리는 0 / 모든 머리가 같은 값 / 0).
의미는 밝히지 못했지만 이 문제와는 관계없습니다.

## 7. 시도했다가 되돌린 것

- **홀드 머리·꼬리를 동시치기 짝(`isDouble`/`doubleIdx`)에 넣기.** 짝마다 `BaseEnemyObjectController.OnControllerAttacked`에서
  NRE가 났습니다(Star Trace 13곳). 일반 노트(type 1)만 짝으로 둡니다.
